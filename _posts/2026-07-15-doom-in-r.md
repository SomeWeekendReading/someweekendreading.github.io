DOOM is getting closer to my sensitive spot.  


## DOOM Now Runs in R?!

Incorrigibly persistent readers of this Crummy Little Blog That Nobody Reads (CLBTNR) know
that we've followed with some amusement the attempts to port the game DOOM to increasingly
absurd hardware platforms (e.g., [PDF files with internal Javascript]({{ site.baseurl }}/doom-pdf/),
the [Domain Name System]({{ site.baseurl }}/doom-dns), and so on).  

Up until now, it's all been good, clean fun.  On _somebody else's_ platform.  

But now&hellip; they've made it run (using FFI, which cheating, but only sorta) under the
[statistical language R](https://www.r-project.org/), which has been the tool of my trade
in the latter half of my career, and my main data-hacking tool in retirement for about a
quarter century.  

It's _personal_ now.  

From `coolbutuseless` comes a GitHub repository `rdoom`. <sup id="fn1a">[[1]](#fn1)</sup>
As announced on BlueSky:  

<a href="https://fosstodon.org/@coolbutuseless/116883176253902359"><img src="{{ site.baseurl }}/images/2026-07-15-doom-in-r-bluesky-1.jpg" width="550" height="682" alt="coolbutuseless @ BlueSky: DOOM now runs under R" title="coolbutuseless @ BlueSky: DOOM now runs under R" style="margin: 3px 3px 3px 3px; border: 1px solid #000000; margin: 0 auto; display: block;"></a>

On the one hand, there's less here than one might think: it uses the
[doomgeneric](https://github.com/ozkl/doomgeneric) game engine running as native code, and
interfaces to it in various clever ways.  (Demo .wad file included; others work, you just
have to go dig them up.)  

On the other hand, there's more here than one might think: the `tigerfb` R package for
frame buffers, the `nara` R package for native raster image support, and the `audio`
package for all those disturbing sounds.  

So&hellip; a lot of work, and&hellip; "cool but useless" as the author's pseudonym leads
us to believe.
